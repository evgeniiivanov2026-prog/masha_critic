# Нижегородская формула v8.0

Локальный детектор достоверности новостей. Формулы скоринга перенесены из CLI без изменения коэффициентов, порогов потолков и границ вердиктов. Веб-страница и плагин Firefox/Chrome только показывают ответ сервера и сами балл не считают.

Обучение в вебе закрыто. Менять веса может только администратор: в окружении сервера должна быть переменная `NIZHNY_ADMIN_TOKEN`.

## Установка

Нужен Python 3.10+.

```bash
cd nizhny-web
pip install -r requirements.txt
```

Морфология необязательна. Если установлен `pymorphy2` или `pymorphy3`, `mislabel` считается по леммам. Если нет ни того ни другого, слова приводятся к нижнему регистру, программа не падает.

```bash
export NIZHNY_ADMIN_TOKEN='длинный-секрет'
export NIZHNY_LOG_LEVEL=INFO
```

## Запуск

```bash
uvicorn app:app --reload
```

Страница: <http://127.0.0.1:8000/>.

Терминал из того же каталога:

```bash
python3 nizhny.py report
python3 nizhny.py train
python3 nizhny.py feed --limit 10
```

Без TTY команда `python3 nizhny.py` не открывает curses и печатает подсказку.

## Два режима include_url

Режим называется `score_include_url`. В API и на странице поле называется `include_url`.

- **Включён** (по умолчанию в вебе, в плагине и в `POST /api/analyze`). Адрес статьи дописывается в разбираемый текст. Домен попадает в `sources()`, и таблица `DOMAIN_CRED` влияет на credibility. Рядом с баллом стоит пометка «URL статьи учтён».
- **Выключен** — поведение CLI. В текст попадает только то, что и так в нём написано. Отдельный URL записи не подмешивается. Терминальный обход ленты по умолчанию работает так.

Вкладка «Сравнение» считает один текст дважды и показывает `delta_score`.

Короткий текст без первичного источника часто упирается в пол **1.0** в обоих режимах: при нуле совпадений сигмоида даёт активацию 0.5, штраф шума большой. Разница домена видна, когда сырой балл выше пола, например на длинной заметке со словами «согласно отчёту», цифрами и таблицей.

## Фикс 1. Тело статьи доходит до скоринга

Раньше обход ленты вызывал `analyze(text, title=заголовок)`. `split()` при уже заданном заголовке и пустом теле возвращал тело `""`, и в сигналы уходило `"ЗАГОЛОВОК\n"`.

Теперь в разбор передаются заголовок и тело. Если тело забыли аргументом, но оно лежит в `text` следом за заголовком, хвост тоже сохраняется. На карточке `base_quality` видна длина тела: порог `n < 200` снижает качество, `n > 700` и `n > 1500` поднимают.

## Фикс 2. Домен самой статьи

`sources()` по-прежнему ищет URL регулярным выражением внутри текста. У RSS-записи ссылок в теле часто нет, и домен оставался `(none)` с `DEFAULT_CRED = 0.55`. Включённый `include_url` это исправляет. Выключенный режим CLI не трогает.

## Обучение

`POST /api/train` и `POST /api/weights` отвечают 403 без заголовка `X-Admin-Token`, совпадающего с `NIZHNY_ADMIN_TOKEN`.

Подбор весов идёт на обучающих 80% выборки. Наружу отдаются F1, precision, recall и accuracy тестовых 20%. Разбиение стратифицировано по метке, `random_state = 42`. Метки не инвертируются: `1` — шум, `0` — достоверная новость. `_pred` возвращает 1, если `H >= 0.5` или credibility `< 0.45`.

Формула F1 прежняя: если верных срабатываний на шум не было (`tp = 0`), F1 равен `0.0`.

Веса пишутся атомарно в `weights_v80.json` (`tempfile` + `os.replace`) и подхватываются после перезапуска процесса.

## API

Ошибки запроса: JSON `{"error": "..."}`. Сетевой сбой `/api/fetch` и отдельного фида в `/api/feed` — это 200, поле `ok: false` или элемент `errors`, не 500.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | страница |
| GET | `/api/health` | `ok`, `version`, `morph`, `weights` |
| POST | `/api/analyze` | разбор текста |
| POST | `/api/fetch` | скачать страницу и разобрать |
| POST | `/api/feed` | RSS/Atom, `items` и отдельно `errors` |
| POST | `/api/compare` | `with_url`, `without_url`, `delta_score` |
| POST | `/api/train` | только администратор |
| GET/POST | `/api/weights` | чтение всем, запись только администратору |
| GET | `/api/lexicon` | семь сенсоров и их шаблоны |

## Плагин Firefox и Chrome

Каталог `extension/` — Manifest V3.

- Chrome: `chrome://extensions` → режим разработчика → «Загрузить распакованное» → каталог `extension`.
- Firefox: `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» → `extension/manifest.json`.

Плагин читает заголовок и текст открытой вкладки и отправляет их на `http://127.0.0.1:8000/api/analyze`. Сервер должен быть запущен. Кнопки обучения в плагине нет.

## Отличия от CLI

- Веб по умолчанию включает `include_url`. CLI в `score_all` оставляет его выключенным.
- CLI тоже передаёт тело в `analyze` (фикс 1), поэтому баллы ленты отличаются от старого вызова `analyze(text, title=...)`.
- `dataset.jsonl` и `weights_v80.json` лежат рядом с `core.py`, а не в текущем каталоге процесса.
- В журнале обучения четыре метрики и размеры train/test. Дашборд TUI по-прежнему показывает F1 на всей выборке: эта цифра смещена вверх.
- Запись весов атомарная. Кэш загрузчика и веса держатся под `threading.Lock`.

## Известные ограничения

- Часть фидов по умолчанию мертва в 2026 (`feeds.reuters.com`, `apnews.com/hub` отдают 403). Они остаются в списке и попадают в блок ошибок — это ожидаемо.
- F1 считается на малой выборке SEED, оценка шумная. Реальная проверка — на большом размеченном наборе, которого сейчас нет.
- `f1 = 0.0` при отсутствии tp — свойство исходной формулы, не баг веба.
- Без pymorphy2/pymorphy3 метрика mislabel грубее (fallback на `lower()`).
- Скор — эвристика, не фактчекинг. Не единственное основание для редакционных решений.
- Нулевое число совпадений сенсора даёт активацию `sigmoid(0) = 0.5`, потому что так написан исходный расчёт при margin 0. Шаблон капса скомпилирован с `re.I`, как исходный `finditer(..., re.I)`, поэтому `[A-ZА-ЯЁ]{5,}` совпадает и со строчными словами длиннее четырёх букв.
- Потолок «одинокий источник ≤ 3» срабатывает и на домене `(none)`.

## CHANGELOG переноса

Имена сохранены: `Parser`, `Analysis`, `Finder`, `Trainer`, `Weights`, `Fetcher`, `extract_article`, `parse_feed`, `dedup`, `date_filter`, `LEXICON`, `SEED`.

Добавлено: аргумент `include_url` у `Parser.analyze`, поле `Analysis.url_included`, поля `Article.primary` и `Article.caps`, метрики precision/recall/accuracy и стратифицированное разбиение. `evaluate`, `fetch_page`, `run_feeds`, `train_model` — обёртки для HTTP, формул в них нет.

Коэффициенты не менялись: база `3.0`, credibility `3.2`, data `2.0`, quality `2.4`, штраф шума `2.6`, насыщение `0.6`, mislabel `0.5`, первичный источник `+0.4` иначе `-0.5`, опровержение `-1.3`. Потолки: `3.0` / `3.4` / `1.4` / `2.0`. Вердикты: `≥ 4` добросовестная, `≥ 3` спорная, `≥ 2` слабодостоверная, иначе манипулятивная. Итог зажат в `[1.0, 5.0]`.

Исходного файла в репозитории не было. CLI восстановлен по тексту `nizhny.py`, который пришёл вместе с задачей, и вызывает этот же `core.py`.
